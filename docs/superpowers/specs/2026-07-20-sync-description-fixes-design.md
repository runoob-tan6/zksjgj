# v3 同步描述修复设计

## 目标

修复岩性描述自动同步中的三个问题，同时保持现有 UI、触发方式和保存格式不变：

1. 源层地层时代为空时不得匹配其他地层时代。
2. 跨钻孔同步撤销后必须可以立即重做，且当前钻孔保持为同步来源。
3. 同步数量提示不得被普通修改提示立即覆盖。

## 当前行为与根因

编辑“岩性描述 .-h”后，`BasicLayerModel.setData()` 在完成源编辑事务前发出同步信号。同步动作因此先于源编辑进入撤销栈，且随后五个基础文件脏标记会覆盖同步状态提示。

同步匹配使用 `(not formation or layer.formation == formation)`，把空地层时代当成通配条件。跨孔撤销通过 `_apply_snapshot()` 恢复目标孔时会把当前钻孔切到目标孔，但重做记录仍保存在源孔的撤销管理器中，因此重做按钮不可用。

## 设计

- 匹配条件使用岩性代号、地层时代和风化程度三项严格相等；仍只填充其他钻孔中的空描述，不覆盖已有描述。
- `BasicLayerModel.setData()` 先执行 `after_set_data`，完成源编辑撤销记录和基础文件脏标记，再发出描述同步信号。同步状态提示因此成为最终提示。
- 同步产生的跨钻孔动作始终使用 `CompositeUndoAction`，即使只影响一个钻孔。
- 撤销和重做复合动作时恢复目标孔数据但不改变当前钻孔或树选择，使操作继续使用源孔的撤销管理器。
- 普通单钻孔编辑继续使用现有 `_apply_snapshot()` 选择和刷新逻辑。

## 测试

专项 UI 测试覆盖：

- 三项条件完全相同时同步空描述，并标记目标 `h` 后缀为脏。
- 空地层时代只匹配空地层时代，不匹配非空值。
- 已有目标描述不被覆盖。
- 通过表格模型编辑后，状态栏最终显示同步钻孔数量。
- 同步到一个和多个目标孔时，撤销/重做都保持源孔选中并正确恢复全部描述。

全量 pytest、Ruff、mypy、v2 哈希校验和 EXE 启动冒烟必须继续通过。
