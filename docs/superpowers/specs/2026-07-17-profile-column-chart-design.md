# v3 剖面图与柱状图管理设计

## 1. 目标

在钻孔数据编辑工具 v3 中调整剖面与柱状图的用户概念，并保证相关文件作为完整文件组安全维护：

- 树分组“剖面及柱状图”更名为“剖面图”。
- 树分组“项目配置文件”更名为“柱状图”。
- 剖面图支持右键整体重命名。
- 自动维护岩钻孔柱状图 `0yzk.-zkt` 和土钻孔柱状图 `0nzk.-zkt`。

现有窗口结构、标签页、钻孔编辑流程和保存入口不变。

## 2. 剖面图文件组

剖面图由同一前缀的主文件和全部附属文件组成。例如：

```text
H8
H8.-d0
H8.-g
H8.-k
```

它们属于一个 `ProfileFile`。整体重命名不限定附属后缀；凡是以原剖面名加 `.-` 开头、已经被项目加载为该剖面的附属文件，都必须随主文件一起重命名。

### 2.1 右键操作

剖面主节点的右键菜单保留复制和删除，并新增“重命名剖面文件”。用户输入必须符合现有剖面名规则 `H数字` 或 `Z数字`，忽略首尾空格并统一为大写。

以下情况拒绝重命名并沿用现有“提示”对话框风格：

- 新名称格式无效。
- 新名称已经存在于项目模型。
- 项目目录中已经存在同名主文件或任一将要生成的同名附属文件。

输入与原名称相同则不产生修改。

### 2.2 模型与保存

`ProfileFile` 增加 `old_name`，记录本次未保存重命名前的最初名称。连续执行 `H8 -> H9 -> H10` 时仍以 `H8` 为磁盘旧前缀，避免遗留中间名称。

重命名时更新：

- `ProjectData.profile_files` 的字典键。
- `ProfileFile.name`。
- `ProfileFile.path` 为项目目录中的新主文件路径。
- `ProfileFile.modified = True`。
- 当前树选择和编辑上下文。

保存事务先生成新主文件和全部新附属文件，再备份并删除旧前缀文件。全部操作进入同一个 `SaveTransaction`；失败时恢复旧文件，新文件不得残留，模型保持未保存状态。成功后清除 `old_name`。

## 3. 柱状图文件

柱状图只管理以下两个文件：

| 文件 | 钻孔类型 | 内容 |
| --- | --- | --- |
| `0yzk.-zkt` | 岩钻孔 `ZK` | 全部 ZK 钻孔号 |
| `0nzk.-zkt` | 土钻孔 `NZK` | 全部 NZK 钻孔号 |

内容采用自然排序，每行一个钻孔号，最后一行为结束标记：

```text
ZK1
ZK2
ZK10
★
```

即使某一类型当前没有钻孔，对应文件也必须存在于项目模型，内容仅为 `★`。

### 3.1 自动同步时机

统一的 `synchronize_column_charts(project)` 应用服务在以下时机调用：

1. 项目文件全部加载完成后。
2. 新增或复制钻孔后。
3. 删除钻孔后。
4. 修改钻孔编号后。
5. 生成保存摘要和执行保存前。

同步服务比较规范内容；缺失或内容不同才把对应 `ProfileFile` 标记为 `modified`。内容已正确时不得制造无意义的脏状态。

### 3.2 落盘行为

加载时只更新内存模型和树，不直接写磁盘。缺失文件在“柱状图”分组中立即显示为待保存项；用户使用现有“保存数据”后，由事务保存创建或更新文件。这保持 v3 的“加载不写磁盘”原则。

保存前强制再次同步，因此即使柱状图显示内容被编辑，最终写入磁盘的仍是当前项目钻孔清单的规范内容。

新文件使用 UTF-8 和现有 v3 默认换行规则；已有文件继续保留原编码和换行风格。内容以 `★` 结束且不额外追加空记录。

## 4. 界面行为

- “剖面图”分组显示剖面主文件及附属文件。
- “柱状图”分组显示 `0yzk.-zkt` 和 `0nzk.-zkt`。
- 工具菜单“新增剖面文件”保持不变。
- 剖面主节点右键菜单顺序为：复制、重命名、分隔线、删除。
- 柱状图内容继续使用现有数据文件编辑页显示；保存前同步服务负责恢复规范内容。
- 保存确认中的“项目配置文件”文字改为“柱状图文件”，剖面相关提示继续使用“剖面文件”。

## 5. 错误处理

- 重命名冲突在修改模型前检查，不允许覆盖已有文件。
- 保存事务失败沿用现有“保存失败”错误路径，并保留所有脏状态。
- 柱状图同步只依赖内存中的 `ProjectData`，不因单个旧柱状图内容无法解析而阻止项目加载；旧内容会被规范清单替换。
- 自动同步不得删除 `project_files` 中除 `0nzk.-zkt`、`0yzk.-zkt` 之外的其他兼容项目文件。

## 6. 测试

### 6.1 应用层

- 无柱状图文件时创建两个模型项。
- 空 ZK 或 NZK 集合生成仅含 `★` 的内容。
- 钻孔号自然排序并正确分类。
- 内容相同时不标脏，内容变化时标脏。
- 新增、复制、删除和改名后同步结果正确。

### 6.2 保存集成

- `H8/H8.-d0/H8.-g/H8.-k` 重命名后只生成 `H9` 文件组并删除旧组。
- 连续两次未保存重命名仍从最初前缀迁移。
- 任一原子替换失败时旧组全部恢复，新组不残留。
- 缺失的 `0nzk.-zkt`、`0yzk.-zkt` 在保存后生成。
- 已有柱状图保留原编码和换行。

### 6.3 UI

- 两个分组显示新名称。
- 剖面主节点右键包含“重命名剖面文件”。
- 有效重命名更新树选择；格式错误和名称冲突保持原模型。
- 保存确认显示“柱状图文件”。

## 7. 验收条件

1. 剖面图四文件示例及任意其他附属后缀可整体重命名。
2. `0yzk.-zkt` 始终对应全部 ZK，`0nzk.-zkt` 始终对应全部 NZK。
3. 两个柱状图缺失时会在加载后进入待保存状态，保存后实际生成。
4. 全量 pytest、Ruff 和 mypy 通过且无警告。
5. v2 哈希清单保持不变。
6. Windows EXE 重新构建并通过主窗口启动冒烟。

## 8. 用户确认

用户已确认柱状图格式、钻孔分类、自动同步时机，并批准本设计直接实施。
