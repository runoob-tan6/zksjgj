# v3 自动同步孔深持久化修复设计

## 目标

在“基础数据”修改钻孔最深层的层底深度后，主文件孔深继续即时同步，并在保存后真实写入钻孔主文件。重新加载项目时，主文件孔深与基础数据最深深度必须保持修改后的相同值；撤销和重做也必须同时恢复两处数据。

## 根因

`MainFilePage._sync_depth_from_layers()` 已修改内存中的 `main.lines[1]` 和套管深度字段，因此界面显示一致。但基础数据编辑只发出 `.-c/.-b/.-d/.-g/.-h` 的变更信号，主文件没有加入 `dirty_suffixes`。`SaveService` 在存在具体脏后缀时只写这些目标，导致主文件被跳过。

普通单元格编辑还会在联动信号执行前拍摄撤销操作的完成快照，所以重做可能恢复已修改的层底深度，却恢复旧主文件孔深。

## 方案

自动孔深实际变化后复用现有 `field_changed` 信号，把 `main` 纳入脏后缀。基础数据普通编辑先完成全部文件脏标记和孔深联动，再调用 `end_change` 拍摄完成快照。新增、删除行本来就是这个顺序，保持不变。

不修改 `SaveService` 的后缀选择策略，不强制每次 `.-c` 变化都重写主文件；只有自动同步确实改变孔深时才标记主文件。

## 测试

- 编辑最深层深度后，内存主文件孔深更新且 `dirty_suffixes` 同时包含 `c` 和 `main`。
- 保存并重新加载后，磁盘主文件孔深和基础数据最深深度均为新值。
- 撤销同时恢复旧孔深和旧最深深度，重做同时恢复新值，并保留主文件待保存状态。
- 完整 pytest、Ruff、mypy、v2 哈希、PyInstaller 构建和 EXE 冒烟继续通过。
