# v3 `.-h` 描述空行修复设计

## 目标

保存钻孔描述文件时，只写出同时具有层底深度和非空描述的完整记录，避免 `.-h` 文件出现空描述行或孤立的 `#深度` 行。v2 源码、v3 UI 和旧文件读取行为均保持不变。

## 方案

修复限定在 `render_h_file()`。每层的深度与描述先转换为字符串并去除首尾空白；两者均非空时才按 `#深度`、描述两行输出。缺少任一字段的层不写入 `.-h`，全部层都不完整时文件内容仅为结束标记 `★`。

不修改通用 `make_file_text()`，避免影响其他允许空字段的文件格式；不收紧 `parse_h_file()`，继续兼容既有不完整文件。

## 验证

- 单元测试覆盖空描述、混合完整与不完整记录、纯空白字段和首尾空白清理。
- 保存服务集成测试确认磁盘上的 `.-h` 没有空行，并保留既有编码与换行约定。
- 完整 pytest、Ruff、mypy、v2 哈希、PyInstaller 构建和 EXE 冒烟继续通过。
