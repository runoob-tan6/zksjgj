# v3 代码审查问题整改设计

## 目标与边界

按代码审查清单逐项修复已核实的问题，提高 v3 的正确性、数据安全、可维护性、性能和可观测性。界面布局、显示文字和用户操作流程保持不变；v2 不参与修改。

整改以生产调用路径为准。审查文档中过时或夸大的描述不机械照搬，例如 `SaveService` 已有生产路径测试，`id(borehole)` 的历史也会在加载和删除时清理；但相应的重复实现和脆弱标识仍应消除。

## 分阶段方案

### 1. 后台任务生命周期

`TaskRunner.running` 表示整个任务生命周期尚未完成，而不仅是线程仍在执行。线程结束后，成功/失败回调仍可能排队等待主线程处理，因此只有 `_handle_finished()` 完成回调清理后才把 `worker` 置空。`running` 直接依据 `worker is not None`，避免界面提前退出忙碌状态或测试偶发漏收回调。

### 2. 单一保存入口

集成测试迁移到生产使用的 `SaveService`。删除 `file_writer.py` 中直接写入、直接删除和自建备份的旧保存入口，仅保留解析结果的纯渲染与编码辅助函数。所有项目保存继续统一经过 `SaveTransaction`。

### 3. 无副作用的保存摘要

`summary()` 只收集当前状态，不调用会修改柱状图文件的同步操作。柱状图预期内容由纯计算函数生成并参与摘要比较；真正写回模型的同步只在 `save()` 命令中执行。关闭窗口检查未保存状态不会制造新的修改标记。

### 4. 事务与状态加固

事务提交使用显式异常替代生产 `assert`，成功后清空操作，失败后也不保留不可重放的中间状态。`SaveService.save()` 每次调用建立独立事务和局部结果，防止重复保存累计旧路径和计数。设置文件路径运行时求值，写入失败时保留应用可用性并记录诊断。校验函数返回消息而不修改实体。

### 5. 共享领域规则

在领域层提供自然排序基础解析，并分别导出钻孔和剖面排序键，统一项目列表、树和 Excel 导出行为。文件读取通过一个基础设施函数一次取得文本、编码和换行符，解析和保存复用该结果。主文件字段索引使用具名常量，孔深与套管深度联动封装为领域操作。撤销管理器用稳定的钻孔前缀键，并在重命名时迁移历史。

### 6. 日志和备份保留

应用启动时配置滚动文件日志并安装未捕获异常钩子；后台任务记录完整 traceback，同时仍向界面返回简短错误文本。事务保存成功后按每个目标文件保留最近 20 份备份，并清理更旧备份，不影响失败回滚所需文件。

### 7. UI 渐进解耦

先把跨组件需要的私有操作提升为公开 API，再提取低风险协作者：撤销控制器负责快照和历史，项目文件操作对象负责命名校验与模型变更，树控制器负责列表构建、查找和选择。`MainWindow` 保持现有信号、槽和交互顺序，只做组装与流程协调。重复变更处理器和局部导入在这一阶段收敛。

## 测试策略

每一阶段先增加会失败的回归测试，再修改实现。保存路径用集成测试覆盖真实磁盘写入、重命名、删除和重复保存；查询纯度、自然排序、编码/换行、事务重入、备份保留和设置失败使用单元测试；任务生命周期和 UI 协作者使用 pytest-qt。

每个检查点运行相关测试，全部完成后运行完整 pytest、Ruff、mypy 和 v2 基线哈希验证。由于隔离工作树不包含用户未跟踪的 v2，最终 v2 哈希在主工作区只读执行。
