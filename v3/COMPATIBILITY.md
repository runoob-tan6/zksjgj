# v3 兼容性与验收报告

## 结论

v3 从 v2 源码完整复制后独立优化。窗口标题、应用版本、包名、命令名和 EXE 名称更新为 v3；其余窗口尺寸、菜单、快捷键、分栏、标签页、按钮、提示文字和正常操作入口保持 v2 行为。

此前 `codex/v3-refactor` 分支的三栏界面没有进入本版本。

## 功能入口

自动化功能清单确认保留以下入口：

- 文件：选择项目、重新加载、打开文件夹、退出。
- 编辑：撤销、恢复。
- 工具：新增钻孔、新增剖面文件、校验项目、导出试验汇总、保存数据。
- 工作区：钻孔树、基本信息、试验数据、标贯分析、数据文件、原始文本、校验结果。
- 树操作：钻孔/剖面复制和删除、附属文件新增和删除、项目配置文件新增和删除。
- 外部输入：项目文件夹拖放、XLSX/XLS/CSV 表格拖放导入。

源码清单测试要求 v2 的 24 个 Python 模块和全部主要 `MainWindow` 命令方法继续存在；v3 允许新增内部模块但不允许删除基线入口。

## UI 对照

- 最小窗口：980 x 640。
- 默认窗口：1180 x 760。
- 布局：左侧钻孔树、右侧六标签页。
- 六个标签页分别在独立进程中用同一 Qt 版本、窗口尺寸和空项目状态渲染。
- `window.grab()` 不包含操作系统标题栏，因此 v2/v3 允许的标题版本差异被自然排除。
- 六组 PNG 字节完全一致，像素差异为零。

## 文件兼容

合成旧项目覆盖：

- ZK 主文件及固定 16 行字段。
- `.-b/c/d/g/h/q` 已知文件。
- `.-x` 未知钻孔附属文件。
- 剖面主文件和剖面附属文件。
- `0nzk.-zkt` 项目配置文件。
- GBK、UTF-8、CRLF 和 LF。

验证结果：只加载不改变任何字节；编辑一个岩性代号只更新 `.-c`；未知附属文件保持原字节；更新文件保留原编码和换行风格。

## 稳定性修复

1. 多文件保存改为同目录临时写入、持久备份、原子替换和失败逆序回滚。
2. 保存失败不清除钻孔、剖面或项目配置文件的脏状态。
3. 加载、保存、导入和导出使用单一后台任务运行器，拒绝重叠任务并统一释放线程。
4. 关闭窗口时等待后台任务，不再销毁仍运行的 `QThread`。
5. 待删除剖面纳入未保存检查，切换项目或关闭时不会静默丢失操作。
6. LF 文件在 Windows 保存后继续使用 LF，不再被隐式转换为 CRLF。
7. 导入拒绝 `NaN` 和正负无穷深度；导出保留非有限原始文本，避免 openpyxl 静默写成空单元格。
8. 状态栏总深度忽略非有限输入，不再显示 `nan m`。

## 性能优化

- 导出操作只计算一次钻孔自然排序，并把结果复用于试验汇总、钻孔汇总、标贯分析和 CSV 输出。
- 文本保存先做规范化内容比较，未变化文件不进入事务和备份。
- 事务在任何目标替换前先完成全部内容编码、临时写入和原文件备份，减少半提交状态。

## 边界

自动化使用合成项目，不包含用户真实工程数据。文件名、字段顺序、结束标记、编码、换行、保存集合和导出结构已经覆盖；最终用于生产前仍应把一个真实项目复制到临时目录，用现有 CAD/FAS 插件完成一次成图验收。该现场验收只操作项目副本，不应写入原项目或 v2 目录。
